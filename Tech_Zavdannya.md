Технічне завдання — TaskFlow

1. Загальні відомості
Назва проєкту:	TaskFlow
Тип ПЗ:	Вебзастосунок (SPA + REST API)
Замовник:	Навчальний заклад (кафедра / школа)
Цільова аудиторія:	Студенти, учні, викладачі, вчителі

2. Призначення та мета системи
Призначення: централізований облік, моніторинг і управління домашніми завданнями між викладачем і студентами.
Мета: оптимізувати навчальний процес; запобігти зривам термінів здачі робіт; дати викладачу зручний інструмент для публікації та перевірки завдань.

3. Ролі користувачів
Студент / Учень — переглядає завдання, прикріплює розв'язання, змінює статус, отримує нагадування.
Викладач / Вчитель — створює завдання, встановлює дедлайни, перевіряє роботи, виставляє статуси.

4. Основний функціонал
- Створення, редагування та видалення завдань викладачем.
- Фільтрація і пошук завдань студентом за предметом, статусом, пріоритетом.
- Зміна статусу завдання: Нове → У процесі → На перевірці → Завершено (+ Зараховано / Повернуто на доопрацювання).
- Прикріплення файлів (до 20 МБ) або посилань до завдання.
- Email- та in-app сповіщення за 72, 24 і 2 години до дедлайну.
- Візуальний календар дедлайнів.
- Аналітика вчасно зданих робіт.
> Повний перелік вимог — у \[`/requirements/requirements.md`](./requirements/requirements.md) (5 FR + 5 NFR) і \[`/requirements/user-stories.md`](./requirements/user-stories.md).

5. Технічний стек (попередній)
Frontend: React + TypeScript, TailwindCSS
Backend:	Node.js + Express (REST API)
База даних: PostgreSQL
Автентифікація: JWT, bcrypt (хешування паролів)
Сповіщення:	SMTP (email) + WebSocket (in-app)
Деплой: Docker + GitHub Actions (CI/CD)

6. Модель життєвого циклу
Обрана модель: Ітеративно-інкрементна (Iterative-Incremental).
Обґрунтування: Проєкт має чіткі логічні блоки, які можна розбити на інкременти. Вимоги можуть уточнюватися в процесі (типово для навчального проєкту). Можна отримати MVP уже після 1-ї ітерації та демонструвати прогрес. Знижує ризики порівняно з каскадною (Waterfall), яка не допускає повернень.

Короткий опис ітерацій:
№	Інкремент	Тривалість
1	MVP: авторизація, CRUD завдань, базові статуси	2 тижні
2	Прикріплення файлів, фільтрація, пошук	1 тиждень
3	Сповіщення (email + in-app), календар	1 тиждень
4	Аналітика, рефакторинг, тестування	1 тиждень

7. Етапи розробки (SDLC)
Аналіз вимог — SRS, user stories, use case diagram (виконано, лаб. №2).
Проєктування — архітектура, схема БД, API-контракти.
Реалізація — за інкрементами з п. 6.
Тестування — unit, integration, E2E.
Впровадження — деплой на хостинг, навчання користувачів.
Супровід — виправлення багів, оновлення.

8. Критерії приймання
Проєкт вважається готовим, коли:
- усі FR-1…FR-5 реалізовані та покриті тестами;
- NFR-1…NFR-5 підтверджені вимірюваннями (навантажувальне тестування, аудит безпеки);
- усі user stories (US-1…US-4) мають виконані acceptance criteria;
- система розгорнута на тестовому середовищі та доступна за публічним URL;
- README.md і документація в `/requirements` оновлені.

9. Обмеження
- Проєкт реалізується силами навчальної команди (без зовнішнього фінансування).
- Хостинг — безкоштовний рівень (Render / Railway / Vercel).
- Підтримка лише двох мов: українська, англійська.
- Браузери: 2 останні версії Chrome, Firefox, Safari, Edge.
